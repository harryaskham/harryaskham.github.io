# Session summary — bd-e45c30 Android terminal keepalive shell compatibility

## Goal

Fix the Android agent terminal startup failure where embedded terminal sessions attempted to run the keepalive shell loop through an argv shape that some Android terminal subprocess paths interpreted as a bad executable, producing exit 127 and `No such file or directory` for the whole `trap ... sleep/read ...` command.

## Bead(s)

- `bd-e45c30` — Fix shell command compatibility for Android terminals
- Related investigation: `bd-245e3c` — Investigate shell script error on Android app terminals

## Before state

- Agent terminal keepalive was launched as `/system/bin/sh` with args `-c` and an inline `trap : TERM INT; while true; ...` script.
- Reported Android error shape: `c: trap : TERM INT; while true; ...: No such file or directory`, exit code 127.
- Earlier `bd-8ba662` already fixed missing `PATH`/`HOME` and sleep fallback, but the new report showed an argv / `-c` interpretation incompatibility remained.

## After state

- Keepalive script text is generated by `termuxAgentKeepAliveScriptText()` with POSIX-friendly `trap`, `command -v sleep`, and `read -t` fallback.
- Script is written to the app-private files dir as `termux-agent-keepalive.sh` via `writeTermuxAgentKeepAliveScript(context)`.
- `TerminalSession` now launches `/system/bin/sh <app-private-script>` via `arrayOf(keepAliveScript.absolutePath)`, avoiding `sh -c <inline script>` entirely for this embedded terminal path.
- Existing explicit `PATH=/system/bin:/system/xbin` and `HOME=/data/local/tmp` environment entries remain in place for the earlier `bd-8ba662` compatibility contract.

## Operator-takeaway

The Android terminal error was not just a missing `PATH`; it was also an inline-shell invocation compatibility problem. The terminal now uses a file-backed keepalive script, which is less fragile across Android shell and terminal-library subprocess implementations.
