Validation evidence for bd-232917:

- Before: bd-f39538 made the mobile sidebar drawer manage focus on
  open/close but did NOT trap focus inside while open. Tab past the
  last focusable element in the sidebar escaped behind the visually-
  obscured drawer into the page chrome. The bd-e7c965 modal trap
  only covers .modal-overlay elements; the sidebar is intentionally
  not one.
- After: the global Tab keydown handler now has a `} else {` branch
  after the modal-overlay check. When no modal is on top and
  `#sidebar.open` is present, it reuses focusableElementsIn(sidebar)
  and the same first/last wrap logic, so Tab/Shift+Tab stay inside
  the drawer. Modal still wins when both are stacked (defensive;
  not currently reachable).
- Mobile-breakpoint detection: presence of `.open` on `#sidebar` IS
  the mobile-drawer signal. setMobileSidebarOpen is only called from
  the hamburger button which is only visible on mobile; desktop
  sidebar is always-visible via CSS and never toggles .open.
