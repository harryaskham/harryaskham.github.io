Test design (~165 lines):
- Walks classList.add/toggle/remove/contains/replace calls across
  16 .js files; reads first quoted string argument as class name;
  skips dynamic (variable) class names.
- Defines bundled definition text from 14 .css files + 4 .html
  files (extracts <style>...</style> contents).
- defined_anywhere() looks for `.classname<token-end>` with leading
  `.` as the class boundary (does NOT require non-token before `.`
  because `.` itself is the boundary -- handles compound selectors
  like `.parent.target` and `.a.b.target` correctly).
- ALLOWLIST_SEMANTIC_STATE_MARKERS as Vec of (class_name, justification)
  with 6 entries.
- Orphans = used - defined - allowlist; assert empty with remediation.
- Forward-guard: each allowlist entry must still appear in the used
  set -- otherwise allowlist accumulates dead entries.

ALLOWLIST RATIONALE (6 entries):
1. terminal-ime-stable-anchor (terminal.js IME state marker; visual
   via inline styles).
2. truncated (app.js choices-count state flag; no visual rule).
3. workspace-terminal-pane (workspace-terminal-pane.js pane base;

These are NOT dead toggles -- they are semantic state markers where

DevTools inspectability + future CSS hook + semantic state marking.

DEBUGGING JOURNEY:
First test pass found 43 orphans. Investigation revealed two issues:
1. notifications.html and workspace.html had inline <style> blocks
   not in my html_files list -- added.
2. The `defined_anywhere` lookup had a buggy `before_ok` check that
   required the char BEFORE the leading `.` to be non-token; this
   broke compound-selector matching like `.status-pill.is-live`
   where the `is-live` class is preceded by the `.pill.` boundary.
   Fixed by removing `before_ok` -- the leading `.` IS the class
   boundary, so what precedes it is irrelevant.

After fixes, only the 6 true semantic-state markers remained.
