Validation evidence for bd-a35f10:

- Before: 5 oninput= handlers called autosizeTextarea(this)
  synchronously on every keystroke. autosizeTextarea is a
  classic layout-thrash pattern:
    style.height='auto'        // invalidates layout
    read scrollHeight          // forces synchronous reflow
    style.height=newH+'px'     // invalidates layout again
  Firing 60+ times/sec while typing is wasteful CPU.

- After: new scheduleAutosize(ta) helper coalesces per-textarea
  via WeakMap-keyed requestAnimationFrame. Multiple textareas
  can autosize independently (per-element key, not per-function).
  WeakMap allows removed textareas to be GC'd without manual
  cleanup. Falls back to immediate invocation if rAF or WeakMap
  is unavailable. Visual result identical to immediate autosize:
  height adjustment happens at next paint, same as the character
  the user just typed.

- 5 hot oninput= sites switched (chat-input, quick-bead-text,
  new-bead-description, bead-desc-textarea, quick-bead-refine-text).

- 6 programmatic call sites PRESERVED as direct autosizeTextarea(...)
  because they need height applied before next paint:
    app.js:4467 (post-render); 5163 (focus); 6234 (clear/focus);
    6425 (programmatic); 6464 (programmatic); 6498 (clear input).
