Validation evidence for bd-ca8a3a:

- Before: only `keyboard-help-overlay` (created at app.js:~1716)
  declared `role="dialog"`, `aria-modal="true"`, and an `aria-label`.
  Four other dynamic overlays — `shortcuts-overlay` (~4206), the
  `confirm-overlay` for "Move bead" (~4667), the `image-lightbox`
  (~6831), and the generic `confirm-overlay` from `showConfirm()`
  (~9996) — created `.modal-overlay` nodes with no dialog semantics.
  Screen readers heard their content as inline page content rather
  than as a modal dialog. The bd-e7c965 focus trap and bd-81a12b
  Escape-remove behaviour already worked correctly because they
  targeted `.modal-overlay`, but AT users still got no dialog
  announcement.
- After: each of the 4 constructors now calls
  setAttribute('role','dialog'), setAttribute('aria-modal','true'),
  and a descriptive setAttribute('aria-label', ...):
  - shortcuts-overlay     -> aria-label "Keyboard shortcuts"
  - move-bead confirm     -> aria-label `Move bead ${beadId}`
  - image-lightbox        -> aria-label "Image preview: <caption>" or "Image preview"
  - generic confirm       -> aria-label `opts.title || 'Confirmation'`
- See web/role-dialog-callsites.txt and web/aria-modal-callsites.txt
  for the 5 callsites the attributes now appear at (keyboard-help +
  4 new).
