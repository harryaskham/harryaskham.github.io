Validation evidence for bd-d0ab29:

- Before: 14 sortable <th> in app.js templates (agents and beads
  tables) were `<th onclick="toggleXSort(...)">` with no aria-sort,
  no scope, no tabindex/role/keyboard activation. Screen reader users
  could not tell which column was sorted or that columns were
  sortable; keyboard-only users had no way to sort.
- After: sortableThAttrs() helper emits scope="col" role="button"
  tabindex="0" aria-sort="ascending|descending|none" data-sort-col
  and an onkeydown that invokes the same toggle function on Enter
  or Space (preventDefault on Space to avoid page scroll). Both
  tables alias the helper as `sa(col)` bound to their toggle.
- Non-sortable header cells (Bead, Runtime, Actions, Type, Labels,
  batch-col checkbox) also get scope="col" so the bd-253481 contract
  extends to dynamic templates.

- Real Playwright probe (web/sortable-th-probe.json):
  * Initial agents thead: all 6 sortable headers expose scope=col,
    role=button, tabindex=0; the currently-sorted ID column reports
    aria-sort="ascending"; others report "none".
  * Focus the State header and press Enter → aria-sort flips to
    ascending on State and back to "none" on ID.
  * Press Space on the focused State header → aria-sort flips to
    "descending"; page scroll is suppressed.
