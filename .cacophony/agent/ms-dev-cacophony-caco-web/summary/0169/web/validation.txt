- ENTRY-SCRIPT PRELOAD PARITY: index.html preloads /app.js
  but workspace.html did not preload /workspace.js even
  though workspace.html has 10+ defer scripts and 9

AUDIT METHODOLOGY:
- grep "<link[^>]+preload|preconnect|dns-prefetch" across HTML.
- Only index.html had preload (for /app.js).
- workspace.html had no preload despite being most complex entry.

FIX:
- workspace.html head: + <link rel="preload" as="script"
  href="/workspace.js">.
- Placed just before <link rel="stylesheet">.

WHY:
- <script defer> only starts fetch when HTML parsing reaches
  the <script> tag.
- <link rel="preload" as="script"> in <head> lets browser
  begin network fetch as soon as head is parsed -- in parallel
  with rest of HTML parse and other resource downloads.
- For complex page like workspace.html (~10 scripts + 9
  stylesheets), shaves 50-200ms off entry-script critical path
  on slow connections.

OUT OF SCOPE:
- Preloading xterm vendor bundles -- those load only when a
  terminal pane mounts; preload risks wasted bandwidth on
  non-terminal workflows.

REGRESSION TEST (~30 lines):
- Per (file, href) tuple, assert literal <link rel="preload"
  as="script" href="HREF"> present.
- Iterates index.html / workspace.html.

OPERATOR-VISIBLE EFFECT:
- Faster perceived workspace bootstrap on slow networks.
- Browser starts /workspace.js fetch ~50-200ms earlier.
- No visual change.
