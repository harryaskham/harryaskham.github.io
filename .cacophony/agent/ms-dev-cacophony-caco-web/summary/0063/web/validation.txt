Validation evidence for bd-171bcc:

- Before: workspace-integrated.js pane split handle drag
  called saveLayout() on every mousemove. saveLayout did:
    1. localStorage.getItem (sync read)
    2. push prev state to _undoStack (with O(n) shift at limit)
    3. JSON.stringify(tree)  // whole pane tree
    4. localStorage.setItem (sync write)
  At 60-120 Hz during drag: 60-120 sync localStorage ops/sec
  PLUS 60-120 undo entries per drag action -> undo stack
  full of garbage micro-mutations that made Ctrl-Z useless
  for any other operation.

- After: rAF-throttled visual updates (cache lastEvent,
  apply once per frame). saveLayout() called exactly once
  on mouseup with the final layout. onUp cancels any pending
  rAF so a stray frame can't fire after release. Listener
  uses { passive: true } options form.
