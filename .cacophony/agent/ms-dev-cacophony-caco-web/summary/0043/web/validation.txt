Validation evidence for bd-34d83f:

- Before: 6 Enter handlers bound to text inputs in app.js fired
  on any keydown with event.key === 'Enter', including the Enter
  that commits an IME composition. CJK / Vietnamese / hangul /
  emoji-by-name users lost half-composed text and accidentally
  submitted / saved garbage.
- Affected sites:
  - L1395 (TUI sidebar agent-id input -- Enter connects)
  - L1530 (command palette input -- Enter runs command)
  - L4163 (inline-edit input -- Enter saves; e.g. bead title)
  - L5130 (another inline-edit input -- Enter saves)
  - L6107 (handleChatKeydown -- chat composer; **worst case**)
  - L9558 (agent rename input -- Enter submits)
- After: each migrated handler uses `!isComposing && keyCode !== 229`
  belt-and-suspenders pattern. Modern browsers expose isComposing;
  older Safari fires Enter with keyCode 229 (Process) during
  composition. The 2 surviving bare Enter handlers (L4788,
  L10169) are on OVERLAY elements (not text inputs) where IME
  composition doesn't apply; pinned in test as intentionally
  preserved so a future blanket rewrite cannot regress button
  keyboard activation.

- Direct foreground validation (per revival nudge; not queued/backgrounded):

      -> 1 passed, 0 failed

         failures on main).
