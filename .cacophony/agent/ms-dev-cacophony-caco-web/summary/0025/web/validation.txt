Validation evidence for bd-31d275:

- Before: 6 sidebar elements had role="button" (or tabindex="0") +
  onclick but no onkeydown:
    * 5 nav-submenu-item rows under Agents (running, failed,
      completed, all, artefacts)
    * the kbd-hint "Commands" pill that opens the command palette
  Keyboard users tabbing to them saw a focus ring but Enter/Space
  did nothing. Mouse users were fine.
- After: each of the 6 elements gains the canonical inline handler
  `onkeydown="if(event.key==='Enter'||event.key===' '){event.preventDefault();this.click()}"`.
  Using this.click() means keyboard activation always tracks
  whatever onclick does — no duplication, no drift.

- Direct foreground validation (per revival nudge; not queued/backgrounded):
    cargo test -p caco-web --lib sidebar_role_buttons_activate_on_keyboard_bd_31d275
      -> 1 passed, 0 failed
    cargo test -p caco-web --lib --tests
      -> 432 passed, 11 failed (net +1 pass; same 11 pre-existing
         failures on main).
